# 跃动小子：单机复刻版

竖屏单机 PWA。核心体验是模拟充值、概率开箱、装备成长、战魂/魔兽/魂卡收集、自动战斗和本地虚拟服务器。

## 已实现

- `6 / 30 / 68 / 128 / 328 / 648` 模拟充值档位、疯狂十连充、首次双倍、VIP 1-15、账单与一键领取。
- 人物从 Lv.1 起步，经验、装备、养成消耗、关卡敌人与资源产出使用相互约束的指数成长曲线。
- 12 部位、10 品质装备；每个部位有独立详情、对比、精炼和宝石孔位，并支持单开、十连、百连、流派换装、出售、宝箱升级和成长目标。
- 开箱委托支持批量、保留品质、目标词条、停止条件、极速模式、自动换装与自动出售。
- 暴击、闪避反击、连击、吸血、击晕五套方案会联动装备评分、战魂、魔兽和魂卡编组。
- 战魂 24 个：紫/金/橙自选礼包、出战、1~4 副魂概率合成、六选一精炼、单词条回退和分品质图鉴。
- 魔兽四系 48 格图鉴：16 格兽栏、6 小时自动产蛋、钻石买蛋、批量孵化、跨物种同品质拖动合成、完整下一品质随机池、失败经验精灵、精华升级、4 词条金币洗练、图鉴永久属性和战斗主动技能。
- 魂卡使用独立 30 格图集和三技能槽；重复卡可升阶或分解为魂晶，魂晶用于升级与再召唤，双塔奇兵另有局内六槽战车构筑。
- 主人物统一成长结算：等级、装备、战魂、魔兽图鉴/等级/词条、魂卡和永久养成都实时重算 4 基础、6 战斗、6 抗性、高级词条与战力。
- 双塔奇兵包含银币招募、刷新、同名升星、战车扩建至 6 槽、逐波攻防和胜利奖励。
- 暮光森林捕猎，使用官网公示的 53 个名称与基础概率。
- 动画回合制战斗包含角色与敌人立绘、血条、技能、伤害/治疗飘字、战魂与魔兽协战、倍速、暂停、跳过及自动推关；失败会停止委托。
- 试炼敌人直接读取用户提供的 v148 原作属性表，共 40 章、1480 个有效关卡记录；页面显示原章节、关卡、四基础属性和主要战斗属性，战后按角色/战魂/魔兽/战宠拆分伤害并统计六战斗属性的实际触发。
- 初始角色挑战原表第 1 关约 2~3 回合、第 2 关约 4~6 回合，第 5 关形成首个养成门槛；群雄列表展示的等级/战力与实战使用同一敌人属性，战斗 HUD 显示真实人物等级。
- 主人物外观随等级与装备进度分 5 阶变化，头像、主页与战斗保持同一形态。
- 坐骑包含公开普通/高级刷新概率、马厩、出战和指数培养；符文包含公开卡池、三槽装配和同级升级；宝石包含 12 装备孔位、四色 1~8 级随机/定向合成、批量合成与拆卸。
- 神器包含炉级、动态品质权重、锻造、出战和同品阶材料升阶；战旗包含分段成功率、进度抽取、120 级成长和六主属性切换；领地包含 9 类资源点、每日拉取、刷新和声望成长。
- 每日转盘有两套 9 格不重复奖池；一锤定音、国王宝库、金蛇送福把公开额外掉落道具转换为确定性资源，不把每个活动都做成抽卡。
- 商城与礼包是两套独立界面：商城含钻石热卖、金币仓库、钻石仓库、联盟、功勋、试炼六类货架；礼包含日常、每日特价、成长双轨、特权和月卡。购买支持批量步进、真实库存/每日限购、首次免费刷新和本地模拟账单；疯狂十连充发放全系统材料但不直接跳等级。
- 福利活动与开服日历是两个独立页面；签到、每日奖励、七日奖励、模拟服务器前进一天和 12 小时挂机收益均随成长倍率提升。
- IndexedDB 版本化存档、旧指数装备一次性重平衡、持久化随机种子、完整美术预缓存、离线安装和移动端安全区适配。

## 数据来源规则

优先级为用户截图、官网概率公示、公开攻略、可调默认值。宝箱 30/31 级、战魂精炼、捕猎、符文、宝石、魔兽洗练、战旗和魔兽合成至完美品质的概率来自现有截图或公开资料；缺少可靠资料的数值在游戏概率页和 `docs/fidelity-data-audit.md` 中明确标为本地暂定。

`source-assets/` 只保存研究资料，不进入生产页面。试炼数据由 `source-assets/试炼怪物属性简表(1).pdf` 生成到 `config/trial-monsters.v148.json`；生产界面的装备、战魂、魔兽、人物成长、战斗敌人和宝箱使用本项目生成的原创图集；旧静态原型位于 `legacy-static/`。

## 运行

```sh
npm install
npm run dev
```

默认访问 Vite 输出的本地地址。生产构建：

```sh
npm run build
npm run preview
```

## 验证

```sh
npm test
npm run check:balance
npm run check:config
npm run test:e2e
```

端到端测试使用本机 `/Applications/Google Chrome.app`，以单工作进程覆盖 `390x844` 手机视口和桌面居中模式，并遍历全部玩法入口、委托、流派、充值、战斗、双塔奇兵、战魂、魔兽、魂卡、捕猎、坐骑、符文、宝石、神器、战旗、领地、转盘、背包和活动兑换。

实现与来源自审见 `docs/full-game-audit-v4.md` 和 `docs/fidelity-data-audit.md`。

## GitHub Pages

仓库内的 `.github/workflows/deploy-pages.yml` 会在 `main` 分支更新后自动校验配置、运行逻辑测试、执行数值审计并部署 `dist/`。首次发布时在仓库的 **Settings → Pages → Build and deployment** 中选择 **GitHub Actions**，随后重新运行 `Deploy GitHub Pages` 工作流即可。

Pages 构建会根据 `GITHUB_REPOSITORY` 自动添加仓库路径前缀，本地开发仍使用根路径。玩家存档仅保存在各自浏览器的 IndexedDB 中；清理网站数据或换浏览器不会自动同步。`source-assets/` 中的录屏、截图和 PDF 保留在本机，但已排除在 Git 仓库及部署包之外。
