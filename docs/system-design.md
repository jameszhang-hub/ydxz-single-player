# 跃动小子单机网页版系统设计 v0

> 这是立项时的历史范围稿，不代表当前完成度。现行玩法矩阵、成长约束与发布门槛见 `docs/full-game-audit-v3.md`。

## 1. 产品边界

本项目是个人本机使用的单机网页版本。第一版重点不是还原所有高阶玩法，而是先建立一个可扩展、数据驱动、接近原版页面结构的游戏骨架。

优先级从高到低：

1. 数值准确：宝箱概率、装备属性、商城道具、战斗触发要尽量接近原版。
2. 商城自由：不发生真实支付；原作限购和货币成本保留为玩法约束，资源可通过本地模拟充值与虚拟开服日循环取得。
3. 页面接近原版：竖屏手游 UI，底部/侧边入口、弹窗、红点、品质色、开箱反馈尽量贴近。
4. 新服开局：角色从 1 级或原版新号状态开始。
5. 后续可补：复杂活动、魂卡独立对战、公会 Boss 精确数值、聊天等不阻塞第一版。

## 2. 技术方案

建议使用纯前端 PWA：

- 框架：React + Vite 或 SvelteKit 静态构建。若追求简单，React + Vite 足够。
- 存档：IndexedDB，保留 localStorage 作为轻量设置缓存。
- 数据配置：`config/game-config.v0.json`。
- 运行方式：本地网页服务器或静态文件服务，手机通过同局域网访问，也可后续封装为离线 PWA。
- 目标设备：iPhone 13，390x844 CSS viewport，竖屏锁定。

核心模块：

- `GameStateStore`：玩家、背包、资源、系统进度。
- `ConfigService`：读取 JSON 配置，校验概率和字段完整性。
- `LootEngine`：宝箱、捕猎、神器、魂卡等概率抽取。
- `CombatEngine`：多回合战斗、速度先手、六技能触发。
- `VirtualServerEngine`：50 个虚拟玩家、战力成长、排行、公会。
- `ShopEngine`：商城购买、资源发放、充值模拟。
- `SaveService`：存档导入、导出、重置。

## 3. 页面结构

第一版建议页面：

1. 主城：首页角色、战力、资源条、宝箱入口、功能入口。
2. 宝箱：开箱、十连/快速开箱、装备对比、穿戴/分解、宝箱升级。
3. 背包：装备、材料、资源道具。
4. 角色：基础属性、战斗属性、防御属性、战力构成。
5. 商城：人民币礼包、钻石商城、每日/每周/特权/月卡/活动礼包，点击即获得。
6. 决斗：排行榜、匹配虚拟玩家、战斗过程、胜负奖励。
7. 公会：虚拟公会、成员、商店、捐献占位、Boss 占位。
8. 养成入口：战魂、捕猎、魔兽、领地、坐骑、魂卡、战旗、神器、符文、宝石。

不做单独教学页，首页就是可操作游戏界面。

## 4. 属性模型

基础属性：

- `attack`：攻
- `defense`：防
- `hp`：血
- `speed`：速度

攻击型战斗属性：

- `lifesteal`：吸血
- `crit`：暴击
- `dodge`：闪避
- `stun`：击晕
- `combo`：连击
- `counter`：反击

防御型战斗属性：

- `anti_lifesteal`
- `anti_crit`
- `anti_dodge`
- `anti_stun`
- `anti_combo`
- `anti_counter`

实际触发概率：

```text
effectiveChance = clamp(attackerSkill - defenderResist, 0, cap)
```

`cap` 先按 100% 配置，若截图显示原版有上限再调整。

## 5. 战斗规则

决斗为多回合，直到一方 HP 小于等于 0。

先手：

- 速度高者先手。
- 速度相同：玩家默认先手，或按配置随机。

单次出手流程建议：

1. 判断攻击者是否处于击晕状态；若是，跳过本次出手。
2. 判断目标是否触发闪避。
3. 若闪避成功：本次不造成伤害，不能吸血，不能击晕。
4. 若未闪避：计算基础伤害。
5. 判断暴击；暴击伤害为 2 倍，暴击时不能被闪避这一条在流程上通过“先判定暴击或暴击锁定命中”实现。需要截图/录屏确认原版顺序。
6. 判断击晕；成功则目标下次出手跳过。
7. 造成伤害。
8. 判断吸血；按伤害比例回复。
9. 判断反击；目标额外出手一次，反击是否可触发连击等由配置控制。
10. 判断连击；连击为第二次出手，第二次也可触发其余技能。

根据你提供的信息，连击的第二次出手也可以触发吸血、暴击、闪避、击晕、反击、连击。为了避免无限循环，第一版配置 `maxComboChain = 3`，若原版存在更高连击链再调整。

## 6. 宝箱和装备

宝箱：

- 宝箱等级影响装备品质概率。
- 需要原版宝箱升级条件。
- 不实现等待时间。
- 开箱后生成装备，玩家可穿戴或分解。

装备：

- 部位待截图确认，配置先保留 `weapon`、`helmet`、`armor`、`belt`、`boots`、`ring`、`necklace`、`bracer`。
- 品质待官网概率图和截图确认，配置先保留白、绿、蓝、紫、橙、红、彩。
- 基础属性：攻、防、血、速度。
- 词条：六战斗属性及六防御属性。
- 战力公式暂定为配置项，后续通过换装截图反推。

分解：

- 根据装备品质、等级、部位产出材料。
- 第一版支持一键分解低品质。

## 7. 商城

商城与礼包是两套独立页面，均为单机资源循环的一部分。

规则：

- 原作显示人民币的项目，单机版仍显示人民币。
- 原作显示钻石的项目，单机版仍显示钻石。
- 点击确认后直接获得道具并写入本地模拟账单。
- 原作可确认的每日限购、库存和刷新成本真实生效；通过推进虚拟开服日重置。
- 不做真实支付。

商城页签：

- 钻石热卖
- 金币仓库
- 钻石仓库
- 联盟商店
- 功勋商店
- 试炼商店

礼包主页签：

- 日常礼包（含战魂、群雄、魂卡、战宠、魔兽、秘宝子页）
- 每日特价
- 成长礼包
- 特权
- 月卡

已由原机确认的钻石档和金币仓库价格直接照录；缺证的货架商品与奖励在数据审计中标为本地补全。

每个商品配置：

- `id`
- `name`
- `tab`
- `priceType`
- `displayPrice`
- `grantItems`
- `visualBadge`
- `source`

## 8. 虚拟服务器

服务器目标：模拟一个新服开局环境，包含你和 50 个虚拟玩家。

虚拟玩家字段：

- 名字、头像、等级、战力、资源、装备评分、公会、上线状态。
- 成长风格：白嫖、微氪、中氪、冲榜、均衡。
- 每日行为：开箱、买商城、决斗、加入公会、提升养成系统。

战力分层：

- Top 1-3：明显领先，可模拟高消费。
- Top 4-10：中高活跃。
- Top 11-30：普通活跃。
- Top 31-50：低活跃或离线。

虚拟玩家不需要聊天，但需要进入公会、排行榜和决斗匹配池。

## 9. 系统模块第一版范围

战魂：

- 回合第 N 次触发。
- 不同战魂有不同被动加成和触发效果。
- 第一版实现上阵、升级、触发日志。

捕猎：

- 概率抽奖。
- 有地图和体力上限。
- 第一版实现地图切换、体力消耗、猎物掉落。

魔兽：

- 多品质、多只魔兽、不同技能。
- 保留合成失败概率，品质越高概率越低。
- 第一版实现抽取、合成、上阵、技能加成。

领地：

- 从随机刷新对象拉取资源。
- 第一版实现刷新、选择目标、收取资源。

坐骑：

- 多品质和数值加成。
- 第一版实现拥有、升级、上阵。

魂卡：

- 卡组、套装、升级、洗练。
- 魂卡对战系统暂不做。
- 魂卡词条加成主角能力。

战旗：

- 资源升级的属性养成。

神器：

- 一个槽位。
- 随机多个被动技能。
- 概率优先从官网公示图整理。

符文：

- 人物独立属性系统。
- 可升级。

宝石：

- 独立系统。
- 合成、升级、拆卸成本。
- 保留失败概率。

公会：

- 成员列表、公会商店、基础排行可做。
- Boss 数值不确定，第一版占位或做简化版。
- 捐献涉及额外仲裁系统，先不做。

## 10. 数据校对流程

数据来源优先级：

1. 原游戏内截图和录屏。
2. 官网概率公示图。
3. 玩家公开截图和攻略。
4. 合理推断默认值。

每条配置必须带 `source`：

- `official_probability_image`
- `user_screenshot`
- `user_video`
- `public_guide`
- `inferred`

概率校验：

- 同一抽奖池权重加和必须为 100% 或 10000 basis points。
- 配置存储统一用 basis points，10000 = 100%。
- UI 展示再换算成百分比。
