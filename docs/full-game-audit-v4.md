## 曲线约束

- 等级经验：`200 × 1.045^L + 47 × L^1.5`，兼顾前期可读性与后期指数增长；Lv.137 需求约 15.8 万，与截图同量级。
- 等级来源：装备分解为主，主线胜利只给当前等级需求约 2.5%；充值、抽取、精炼、魔兽和联盟操作不直接送等级。
- 装备属性：按 `L^1.12 × 品质 × 0.92~1.08`，避免旧版指数爆炸；Lv.135 至尊装备和 Lv.137 总属性有回归区间。
- 培养成本：宝箱、装备精炼、战魂、魔兽、坐骑、符文、神器和战旗均使用连续递增或指数成本；后期不会维持固定低价。
- 资源产出：关卡、挂机、领地、福利、活动与日历奖励随人物等级、主线或开服天数指数增长，和养成成本共同抬升。
- 战力反馈：每次真正改变属性的 store 动作都会记录变更前后战力，角色详情显示逐系统“移除后损失”。
- 试炼敌人：基础四属性、六战斗属性和六抗性直接读取用户提供的 v148 原作表，不再使用本地指数公式；表内百分数进入引擎时统一转换为基点。
- 群雄一致性：NPC 列表的等级和战力会反推实际战斗属性；列表显示值与战斗结算值的误差测试上限为 1.5%，不允许“看起来能打、进去数值换了一套”。
- 旧存档迁移：保留装备身份、部位、等级、品质和词条，按新公式重算旧基础属性，并截断旧公式遗留的超额经验。

## 重复劳动出口

- 开箱：委托批量、自动换装、自动出售、停止条件、极速模式。
- 推关：自动推关，首次失败立即停机。
- 魔兽：批量孵化、两点合成、同品质一键连续合成。
- 战魂/魂卡/捕猎：十次操作；魂卡与捕猎提供重复物一键回收。
- 宝石：一键按流派镶嵌、一键全部卸下、一键最大次数合成。
- 战旗/坐骑/神器/符文：提供十次操作并一次结算结果；坐骑重复项一键遣散。
- 福利：每日一键领取和 VIP 一键领取。
- 商城：疯狂十连充一次发放全系统资源。

## 三向回溯

### 1. 原作还原

- 官网宣传图确认原作的主体识别是红缨闭面小骑士、自动开箱、林间狩猎和角斗；主页、头像与战斗已统一改为五阶段闭面骑士，不再使用露面持锤战士。
- 官网概率长图、用户原机反馈和公开攻略能确认的名称、数量、概率优先进入配置；战魂最多 4 个副位、魔兽 16 格、捕猎 53 项、三魂卡技能位均已纠正。
- 魂卡完整名称/技能、部分魔兽品质、战魂逐档合成率等仍缺原机连续截图；这些数据继续在 `fidelity-data-audit.md` 标为本地补全，页面不得显示成官方值。

### 2. 玩家视角与可玩性

- 主页左右快捷栏、7 个圆形系统入口、12 个装备部位、11 个玩法入口和背包内 10 个资源落点均纳入端到端点击回归；锁定图鉴使用禁用态，不保留无反馈按钮。
- 每次有效养成由 store 统一比较操作前后战力并在提示中反馈；角色详情将总战力拆为等级、装备和各养成系统贡献，避免抽取后“看不出变强”。
- 战斗使用人物/敌人立绘、血条、回合、伤害/治疗飘字、战魂/魔兽协战和播放控制；战后拆分角色、战魂、魔兽、战宠伤害并统计六属性触发，自动推关失败停止。
- 主页、魂卡、战魂、魔兽、符文、捕猎分别使用独立视觉资产；符文 12 张、魂卡 30 张不再复用同一组战魂图。

### 3. 通用游戏逻辑

- 所有收藏系统遵循“获得 -> 首次解锁/图鉴 -> 重复物用途 -> 培养/合成 -> 主人物属性 -> 战斗验证”：装备出售并给经验，战魂作同品质材料，魔兽占格合成，魂卡升阶/分解，捕猎出售，坐骑遣散，符文同级升级，宝石同级合成，神器同阶升阶。
- 概率失败必须有残值：魔兽失败给经验精灵；战魂失败保留主魂和精炼；随机抽取的低级重复物可转为下一轮资源。
- 重复劳动提供批量或自动化出口，但保留关键决策：开箱/推关委托、魔兽一键合成、魂卡/捕猎/坐骑一键回收、宝石一键装卸/合成、十连培养与一键流派优化。
- 等级需求、装备量级、培养成本、关卡和资源奖励使用相互约束的递增曲线；成熟存档的战力贡献总和必须等于显示总战力，单个副系统不得异常吞掉全局预算。

## 发布门槛

1. `npm test` 覆盖概率、战斗轮数、敌人成长、群雄显示/实战一致性、战力预算、旧装备迁移、宝石一键操作、魔兽 16 格合成、魂卡/捕猎/坐骑重复回收、转盘与活动兑换。
2. `npm run check:balance` 输出固定种子的首发属性、第 1~200 关轮数/胜率检查点，以及首日群雄的显示战力和实际战力。
3. `npm run check:config` 校验概率权重与配置结构。
4. `npm run build` 验证 TypeScript、PWA 和生产资源。
5. `npm run test:e2e` 用 `390×844` 与 `1280×900` 顺序执行所有入口和核心操作。
6. 每次新增页面必须保存手机截图并检查动画结束态、横向溢出、文字重叠、重复素材和触控区。
